# 2D 에셋 제작 확장 계획과 추적

목표는 게임 호스트가 바로 소비할 수 있는 고정 격자의 2D 아트다. 기존 정적 build·validate의 파일/JSON 계약을 유지한다. 구현과 예제 원본은 이 폴더에서 관리한다. 입력 **요청 JSON → 로컬 제작 → 검증 → 새 출력 디렉터리 게시**를 공통 경계로 쓴다. 이미지 생성이 필요할 때만 기존 Codex 내장 경로를 사용한다.

먼저 기준 픽셀 보존과 공통 프레임 출력 형식을 정한다. 장비·세트·타일·동작·VFX는 독립 제작한 뒤 같은 CLI와 납품 규칙으로 묶는다. 효과는 프레임별 크롭이나 고립 픽셀 제거를 하지 않는다. 반복 지형의 테두리와 정적 아이콘의 투명 여백도 서로 다른 규칙으로 검사한다. 외부 스킬·폰트·제3자 생성 서버는 도입하지 않는다.

## 진행 기록

1. 기존 정찰병과 스크린샷의 제작 공식을 대조했다. 장비까지 포함해 자동 크롭하면 같은 몸의 머리 크기가 바뀌는 현상을 확인하고, 변형을 원본 격자에서 합성하도록 정했다.
2. 기존 정적 build 출력을 보존하면서 로컬 생산 명령 다섯 개를 연결했다. 늦은 실패나 재실행 때 기존 결과를 건드리지 않도록 새 임시 폴더에서 완성한 뒤 게시한다.
3. 첫 장비안과 독립 생성 세트를 원본 크기로 검토했다. 등불 레이어의 좁은 실루엣과 반듯한 지팡이를 수정했다. 별도 Codex 생성의 도토리·등불은 기준 색이 달라 해당 두 개만 다시 제작했다.
4. 투명 시트의 네 포즈와 VFX를 숲길의 실제 소비 경로에 붙였다. 긴 동일 포즈의 GIF 시간 초과를 회귀 테스트로 재현해 미리보기 한도를 처리했다. 프레임 JSON의 원래 시간은 보존된다. 타일은 요청 크기를 먼저 확인해 잘못된 대형 원본을 경계 검사 이전에 거부한다.

5. 0.2.0을 임시 Codex 홈의 로컬 마켓플레이스에 설치했다. app-server의 skills/list에서 활성화된 스킬을 확인했다. 외부 작업 폴더에서 설치 캐시의 소스로 여섯 번 제작했으며 모두 ready였다. 로컬 명령 실행에 macOS의 네트워크 차단을 적용하고, 별도 소켓 대조군에서 차단을 확인했다.
6. 브라우저 검수 페이지에서 세 가지 애니메이션을 재생했다. 숲길에서는 실제 방향키 입력으로 접지선 y=150을 유지한 네 걷기 포즈, 수집 효과의 0~9 프레임, 정지 중 효과 소멸, 수집 0→1→2→3 및 재시작을 관측했다. 해당 실행에서 브라우저 오류는 없었고 씬 리소스는 모두 로컬 주소에서 읽었다. [플레이 녹화](../examples/forest-scene/evidence/sheet-play.mp4)

## 0.4.0 승인 원본의 로컬 관절 모션

2026-11-08에 `motion`을 설치용 명령 목록과 제작 계약에 추가하고 Python 패키지·플러그인 버전을 함께 0.4.0으로 올렸다. 패키징 목록은 모션 모듈을 포함한다. 원본의 보이는 픽셀을 명시적 부위·부모 관절에 배정하며 자동 분할이나 가려진 신체 생성은 하지 않는다. 중립의 가시 픽셀 복원·팔레트 보존을 검사하고, 동작별 잘림·접촉 오차·중복·루프 차이를 기록한다. 출력은 `action-set`이 그대로 읽는 포즈와 요청이다. 동작별 수정과 의도한 정지의 표현은 [제작 계약](../.agents/skills/pixel-asset-pipeline/references/production.md)에 있다.

[자가 제작 대조군](../examples/production/motion/request.json)은 외부 다운로드나 공급자 코드 없이 만든 여섯 색 부위의 48×48 PNG다. 설치용 스킬 계약 테스트는 저장소 밖 임시 패키지에서 문서의 아홉 CLI 예시를 실행하고 모션 결과를 `action-set`으로 다시 묶는다. 기술 통과는 캐릭터 모션의 외형 승인과 구분한다.

공통 번들 게시에서는 macOS `renameatx_np(RENAME_EXCL)`, Linux `renameat2(RENAME_NOREPLACE)`를 사용해 검사 후 생긴 목적지도 바꾸지 않는다. Windows에서는 기존 비덮어쓰기 rename을 유지한다. 지원 API가 없는 플랫폼은 안전하게 실패한다. 회귀 검사는 제작 중 생성된 빈 디렉터리·기존 파일·내용 있는 디렉터리·깨진 심볼릭 링크의 보존과 임시 작업 정리를 확인한다.

실제 사용자 CLI·플러그인 설치는 수정하지 않았다. Linux/Windows 실행, 게임 엔진 임포트와 사람의 모션 품질 승인은 이 릴리스 검증 범위 밖이다.

검증: macOS의 Python 3.13.3·Pillow 12.3.0에서 `cd assets && .venv/bin/python -W error -m unittest discover -s tests -v` 74개 통과. 문서 예제의 자식 프로세스도 `PYTHONWARNINGS=error`로 실행했다. 모션의 정상 제작·팔레트·중립 보존·동작별 수정·마스크·접촉·의도한 정지·잘림 경고, 잘못된 입력의 비게시, 기존 경로 및 게시 중 생성된 경로의 비덮어쓰기를 포함한다. `git diff --check`도 통과했다. 새 픽셀 읽기는 Pillow 12의 권장 API를 사용하며 구버전에는 기존 API로 호환한다. 다른 Pillow 버전의 실제 실행은 이번에 하지 않았다.

## 0.6.0 연결된 캐릭터 모션과 Rive 내보내기

한 장의 원화와 리그·관절 자세로 만든 PNG 타임라인을 자체 포함된 Rive 파일로 내보낸다. 숫자 입력으로 포즈 시퀀스를 고르고, 반복 여부·프레임 시간·입력 SHA-256을 기록한다. 저장 형식의 근거는 [공식 Rive 런타임 스키마](https://github.com/rive-app/rive-runtime/tree/9afebeb046659cc3ffed906825023012e4d3cd48/include/rive/generated)다. 외부 작성 서비스나 계정, 별도 내보내기 실행 파일 없이 로컬 Python·Pillow로 생성한다.

캐릭터의 팔이 몸에서 떨어지던 사례를 반영해 `motion`에 관절 안쪽을 원화 픽셀로 보충하는 설정과 한 몸 실루엣 검사를 추가했다. 잘림이나 명시적인 몸 연결 검사에 실패하면 검수 그림은 보존하고 추가 동작의 Rive 포즈 목록은 생성하지 않는다. 기존 여섯 동작 파일은 보존한다. 기술 검사 통과만으로 자연스러운 보행을 단정하지 않는다. 지지발의 교대, 팔의 반대 운동, 착지 압축을 실제 재생 속도에서 확인한다.

macOS의 경고 엄격 모드 자산 테스트 110개 통과. 사용자 설치본으로 74포즈를 만든 뒤 Rive로 내보냈다. 최초 파일에서는 어깨·팔꿈치에서 떨어진 실루엣이 확인됐고, 수정 후 74포즈 각각의 투명 배경 위에 8방향 연결 영역이 하나씩 남았다. 공식 웹 런타임으로 재생·동작 전환을 검사했다. 네이티브 iOS/Android와 Rive Editor에서의 편집, 사람의 미술 승인은 확인하지 않았다.

## 0.7.0 동작별 완성 셀과 단일 파일 플레이어

`character`의 작화 경로는 `frames` manifest가 지정한 PNG를 요청의 동작 순서대로 고정하고, 각 셀의 재생 시간을 유지한다. `reference`는 기준 원화 보존용이다. 손바닥, 옆얼굴, 화면 앞쪽의 다리, 가방이 지나며 가리는 옷 등은 그림으로 전달한다. 완성 `character.riv`와 공식 Canvas 2.49.4 JS/WASM·MIT 고지를 포함한 `player.html`은 로컬에서 동작한다. 자동 정면 리그를 명시한 요청은 수정 가능한 초안이며, 지원 자세와 품질 검사를 벗어나면 조사 자료를 남긴다.

2026-11-09 macOS에서 경고를 오류로 처리한 Python 테스트 125개가 통과했다. 실제 Codex 설치와 wheel 내부의 런타임 원본 바이트도 확인했다. 새 작화 샘플은 96×112, 8동작·68개 타임라인 셀이다. 628개 Rive 렌더 표본 중 시간 경계를 제외한 508개가 원본 셀과 픽셀 단위로 일치했다. 연결 영역·파일 일치·런타임 재생 결과와 최종 사용자 미술 수용은 별개다.
