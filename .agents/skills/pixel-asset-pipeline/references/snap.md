# snap · 부드러운 고해상도 원본을 네이티브 격자로 정리

고해상도 PNG에 부드러운 경계·과도한 색이 있으면 리그를 작성하기 전에 사용한다. 사람은 원본의 픽셀 블록과 여백을 보고 크롭·네이티브 격자를 정한다. 자동 격자 추정·자동 리그·가려진 신체 생성은 하지 않는다. 로컬 PNG와 기존 Pillow만 사용하며 원본을 바꾸지 않는다.

```json
{"schema_version":1,"source":"soft-master.png","crop":[0,0,288,288],"grid_size":[48,48],"max_colors":16,"alpha_cutoff":128}
```

```sh
pixel-asset snap --request snap.json --out snap-out
```

상대 원본 경로는 요청 파일 안에 있어야 한다. `crop`은 `[x,y,width,height]`이며 원본 안의 정수 사각형이다. `grid_size`는 최종 `[width,height]`로 각 축 4~128이고 크롭보다 클 수 없다. 위 예시는 6×6 원본 픽셀마다 네이티브 픽셀 하나를 얻는다. 블록 크기가 소수가 되어도 정수 수식으로 각 셀 중심 하나를 선택한다. 격자가 틀리면 크롭 시작 좌표·크기 또는 grid_size를 고쳐 새 출력 경로로 다시 만든다.

`alpha_cutoff`는 1~255이며 기본 128이다. 중심의 알파가 임계값 이상이면 완전 불투명, 아니면 투명 검정으로 만든다. 배경색을 지우거나 새 외곽선을 그리지 않는다. 완전히 불투명한 원본에서는 먼저 호출자가 투명 여백을 저작해야 한다. 출력에는 최소 두 개의 보이는 셀과 투명 셀이 있어야 한다. 모션 호환 규격을 확인한 뒤에도 사람의 새 원본 승인이 필요하다.

`max_colors`는 2~64이며 기본 16이다. 선택적 `palette:["#16191f","#f0a63a"]`를 주면 지정 색으로만 매핑한다. 중복 색은 거부하며 팔레트 길이는 max_colors 이하다. 지정 팔레트가 없고 샘플 색 수가 한도 이하면 그대로 보존한다. 초과하면 median-cut 팔레트와 가장 어두운 샘플 색을 사용한다. 어두운 외곽선 후보를 남기되 새 외곽선을 합성하지 않는다. 각 샘플은 RGB 제곱 거리로 가장 가까운 팔레트 색에 결정적으로 매핑한다. 보간·스무딩·디더링은 없다.

반환 파일:

- `asset.png`: 리그 작성에 사용할 네이티브 RGBA PNG.
- `source-crop.png`: 선택한 원본 크롭. 고해상도 입력의 부드러운 경계를 그대로 보존한다.
- `comparison-native.png`: 왼쪽은 팔레트 정리 전 중심 샘플, 오른쪽은 결과. 네이티브 1×에서 실루엣·작은 디테일을 비교한다.
- `comparison.png`: 왼쪽은 원본 크롭, 오른쪽은 네이티브 결과를 8×로 확대한 그림. 둘 다 최근접 리샘플링이며 블러를 새로 만들지 않는다.
- `inspection.json`: 실제로 디코드한 입력 바이트의 SHA-256, 원본·격자·셀 크기, 입력 색·부분 알파 수, 출력 색·불투명/투명 픽셀 수, 바뀐 색의 셀 수와 출력 해시.

원본·결과를 나란히 보고 눈·손·장비·1픽셀 외곽선과 구멍을 확인한다. 셀보다 작은 디테일이나 셀 중심에서 벗어난 선은 사라질 수 있다. 양자화가 두 부위를 같은 색으로 합치면 팔레트 또는 max_colors를 조정한다. 경계가 밀리면 격자 정렬부터 고친다. 임계값만 낮춰 흐린 테두리를 모두 살리는 방식은 실루엣을 부풀릴 수 있다. 자동 검사 통과와 사람의 품질 승인은 다르며 inspection은 항상 `visual_review:required`, `artistic_acceptance:unverified`다.

검토한 `asset.png`에 맞춰 명시적 부위·관절 리그를 작성하고, 승인한 후에만 motion 요청의 `approved:true`로 사용한다. 기존 리그는 픽셀 배정이 바뀌었을 수 있으므로 새 원본에 다시 검증한다. motion과 action-set의 후속 명령은 [제작 계약](production.md)에 있다.

입력은 정적 PNG만 허용한다. 파일 16 MiB·디코드 4,194,304픽셀·요청 1 MiB 상한을 넘으면 거부한다. 게시에는 기존 공통 비덮어쓰기 계약을 사용한다.

## 참고한 공개 동작과 범위

[Polymation의 Fix AI pixel art](https://polymation.stunning.gg/docs/pixel-art-cleanup)는 격자 복원, 팔레트 제한, 원본과 미리보기 비교 후 필요한 부분만 수정하는 흐름을 설명한다. [공식 도구 목록](https://polymation.stunning.gg/docs/tools)은 snap_pixel_art와 이후의 리그·검수 도구를 구분한다. 이 구현은 그 공개 흐름을 참고해 독립 작성한 로컬 격자 샘플러다. Polymation의 코드·모델·서비스를 포함하거나 호출하지 않는다. 공개 설명만으로 같은 내부 알고리즘이나 품질을 구현했다고 주장하지 않는다.
